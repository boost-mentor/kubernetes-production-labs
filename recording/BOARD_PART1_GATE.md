## 5. MetalLB

Перед сценой C1.9-А проверить две устные/маркерные оговорки:

- MetalLB — controller/speaker для Service `LoadBalancer` в bare metal/on-prem,
  а не универсальная замена cloud-controller;
- L2 требует разрешённого broadcast domain и свободного пула; BGP требует
  реального peer/router и в этой лабе остаётся reference.

Не обещать внешнюю достижимость только по появившемуся `EXTERNAL-IP`.

## 6. Внешний HA

На панелях «Внешняя точка входа» и «Failover» поверх старых значений должны
быть видны актуальные подписи:

- `VIP 10.77.0.10:8080`;
- `HAProxy L4 · mode tcp`;
- health check `GET /readyz`;
- backends: private IP нод, `NodePort 30080`;
- public/floating IP — только SSH;
- active LB определяется командой, это не всегда `lb1`;
- `nopreempt`: после restore VIP не обязан вернуться на `lb1`;
- разрыв измеряется probe log, цифру заранее не обещаем.

VIP лабораторный и живёт в VXLAN пары LB. Публичный вход в production требует
реального адреса и маршрутизации площадки.

## Финальный визуальный проход

- текст читается при рабочем масштабе записи;
- стрелки не пересекают подписи;
- ни одна старая надпись не противоречит списку выше;
- C1.0 → Terraform/Ansible → Kubespray → сети → upgrade → MetalLB → HA → итог
  идёт слева направо без прыжков;
- после этого доску не редактировать в дубле.
